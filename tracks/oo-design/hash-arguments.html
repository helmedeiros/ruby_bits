Hash arguments remove order coupling

{% capture lesson_body %} ## From positional to keyword arguments When you write a method like this: ```ruby def initialize(name, age, role) @name, @age, @role = name, age, role end ``` …every caller must know the **exact order** of arguments: ```ruby Member.new("alice", 30, :admin) ``` If next week you decide `role` belongs earlier, or you want to add a new field, every call site has to change. That's *order coupling*. ### Keyword arguments Keyword args name each value at the call site: ```ruby def initialize(name:, age:, role:) @name, @age, @role = name, age, role end Member.new(name: "alice", age: 30, role: :admin) ``` Two things become easier: - **Callers don't care about order.** They can write `role:` first, or in any order — the names disambiguate. - **You can add new fields without breaking existing callers** (give them defaults). Want to add `team:`? Existing call sites continue to work. ### When positional is fine For methods with **one** argument (or one obvious argument), positional is fine: `square(4)`, `greet("alice")`, `Wallet.new(100)`. The cost-benefit tilts toward keyword args around 3+ arguments or when the meaning of any argument isn't obvious from its value at the call site. ### Required vs. optional Add a trailing colon to make a keyword **required** (Ruby raises `ArgumentError` if missing): ```ruby def shift(point, by:) # by is required point + by end ``` Add a default value to make it **optional**: ```ruby def shift(point, by: 1) # by is optional point + by end ``` {% endcapture %} {{ lesson_body | markdownify }}
