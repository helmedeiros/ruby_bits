Boolean operators

{% capture lesson_body %} ## Boolean operators Ruby has three boolean operators: `&&` (and), `||` (or), `!` (not). They look like other languages — but two things make them more useful than the basics suggest. ### Short-circuit Both `&&` and `||` stop as soon as the result is known. ```ruby false && expensive_call # expensive_call never runs true || expensive_call # expensive_call never runs ``` Use this to guard expensive or nil-prone work: ```ruby user && user.admin? # safe: stops at nil ``` ### They return values, not just true/false This is the part that trips up newcomers. `||` returns the **first truthy operand**, not literally `true`: ```ruby nil || "default" # => "default" false || "default" # => "default" "alice" || "default" # => "alice" (first truthy stops the chain) ``` And `&&` returns the **last truthy operand** (or the first falsy one): ```ruby "a" && "b" && "c" # => "c" "a" && nil && "c" # => nil ``` This makes `||` perfect for default values: ```ruby name = input || "anonymous" ``` ### `!` — logical NOT ```ruby !true # => false !false # => true !nil # => true (nil is falsy, so !nil is true) !"hello" # => false ("hello" is truthy) ``` ### Pitfall: `||=` is not always "if nil" `x ||= y` means `x = x || y`. It assigns `y` to `x` **only when `x` is falsy** — i.e. `nil` or `false`. If `false` is a meaningful value, use `defined?` instead. ### `and` / `or` / `not` keywords Ruby also has English versions, but they have **much lower precedence** than `&&`/`||`/`!`, which can lead to surprises. Stick with the symbols unless you have a specific reason. {% endcapture %} {{ lesson_body | markdownify }}
