Instance vs class methods

{% capture lesson_body %} ## Instance methods vs class methods ### Two kinds of methods A class can define two kinds of method: - **Instance methods** — called on an *instance* of the class. - **Class methods** — called on the *class itself*. ```ruby class Account def deposit(amount) # instance method @balance += amount end def self.zero # class method — note the `self.` Account.new(0) end end a = Account.zero # class method on the class a.deposit(50) # instance method on the instance ``` ### Why two kinds? - **Instance methods** operate on the state of *one specific object*. They use `@balance`, `@email`, etc. - **Class methods** don't depend on a specific instance. They build new objects, look up things by attribute, or expose data about the class as a whole. Common class-method patterns: ```ruby Order.find(42) # look up by id — returns an Order Order.pending # all pending orders Order.from_csv(line) # factory: build from raw data ``` ### Syntax choices Three ways to write class methods — pick one and be consistent: ```ruby class Foo def self.greet; "hi"; end # most common end class Foo def Foo.greet; "hi"; end # rare — repeats the class name end class Foo class << self def greet; "hi"; end # for many class methods at once end end ``` ### Pitfall: `self` inside a class method Inside a class method, `self` IS the class — so `self.new` builds an instance: ```ruby class Account def self.zero self.new(0) # or just `new(0)` end end ``` This is what makes class methods inheritable: subclasses get the same factory behavior automatically. {% endcapture %} {{ lesson_body | markdownify }}
