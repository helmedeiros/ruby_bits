The super keyword

{% capture lesson_body %} ## The `super` keyword When you override a method in a subclass, you sometimes still want the parent's version to run too. `super` is how you call it. ### Basic use ```ruby class Animal def speak "some sound" end end class Dog < Animal def speak parent_sound = super # calls Animal#speak "#{parent_sound} and woof" end end Dog.new.speak # => "some sound and woof" ``` Bare `super` passes the **same arguments** the current method received. `super()` with empty parens passes **no** arguments. `super(x, y)` passes specific ones. ### Common pattern: extend `initialize` Subclasses often need their own state on top of the parent's. Call `super` to let the parent set up its fields: ```ruby class Vehicle def initialize(wheels) @wheels = wheels end end class Car < Vehicle def initialize(wheels, color) super(wheels) # parent sets @wheels @color = color # we set @color end end ``` ### Where does `super` look? Ruby walks the **ancestor chain** — the parent class, then *its* parent, then included modules. The first matching method is the one `super` calls. ```ruby Dog.ancestors # => [Dog, Animal, Object, Kernel, BasicObject] ``` ### Pitfall: bare `super` with no args Bare `super` (no parens) **passes through** the current method's arguments. If you want to call the parent without arguments, write `super()`. ```ruby def initialize(name) super # passes `name` — usually what you want super() # passes NOTHING end ``` {% endcapture %} {{ lesson_body | markdownify }}
