Blocks and yield

{% capture lesson_body %} ## Blocks and yield A **block** is a chunk of code attached to a method call. You've already seen them with `each`, `map`, `times` — the part between `{ ... }` or `do ... end`. This lesson is about writing methods that *accept* blocks. ### Two syntaxes — same thing ```ruby [1, 2, 3].each { |n| puts n } # one-line: braces [1, 2, 3].each do |n| # multi-line: do/end puts n end ``` Style convention: `{ }` for one-liners, `do/end` for multi-line. ### `yield` — calling the block Inside a method, `yield` calls whatever block was passed in: ```ruby def shout_each(words) words.each { |w| yield w.upcase } end shout_each(["hi", "bye"]) { |w| puts w } # HI # BYE ``` You can `yield` multiple values, or none: ```ruby def with_pair yield 1, 2 end with_pair { |a, b| puts a + b } # 3 ``` ### `block_given?` Without a block, `yield` raises `LocalJumpError`. Guard with `block_given?` when the block is optional: ```ruby def maybe_yield yield "value" if block_given? end ``` ### Why blocks? Blocks let a method **invert control** — the caller fills in part of the behavior. That's what `map`/`select`/`reduce` do: they own the loop, you fill in "what to do with each element". ### Pitfall: `do/end` vs `{}` precedence ```ruby puts [1,2,3].map { |n| n * 2 } # prints [2, 4, 6] puts [1,2,3].map do |n| n * 2 end # prints # ``` With `do/end`, `puts` binds to `[1,2,3].map` *without* the block. With `{ }`, the block binds tighter. When chaining, use `{ }`. {% endcapture %} {{ lesson_body | markdownify }}
