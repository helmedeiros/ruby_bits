Inheritance basics

{% capture lesson_body %} ## Inheritance basics Inheritance lets one class **build on** another. The child class starts with everything the parent has, then adds or overrides what needs to differ. ### Syntax ```ruby class Animal def initialize(name) @name = name end def name @name end def speak "some sound" end end class Dog < Animal # Dog inherits from Animal def speak "woof" # overrides parent's speak end end d = Dog.new("rex") d.name # => "rex" (inherited) d.speak # => "woof" (overridden) ``` Use `<` between child and parent. Every Ruby class inherits from something — by default, from `Object`. ### Override what differs, inherit what doesn't In the example above, `Dog` didn't redefine `initialize` or `name` — it gets them for free. Only `speak` changed. ### When inheritance fits Use inheritance when there's a real "is-a" relationship: - `Dog` *is an* `Animal`. ✓ - `SavingsAccount` *is an* `Account`. ✓ - `Cart` *has* `Items`, not "is an" item. ✗ Use composition. If you're tempted to use inheritance just to share code, ask whether composition (an object holding another object) would fit better. ### Pitfall: deep hierarchies Inheritance is rigid. Each layer adds coupling. Two or three levels is usually plenty. If you find yourself building a 5-level deep tower, redesign with composition or modules. ### What's `super`? When you override a method, you sometimes want to **also** call the parent's version. That's `super` — the next lesson covers it. {% endcapture %} {{ lesson_body | markdownify }}
