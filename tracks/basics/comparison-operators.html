Comparison operators

{% capture lesson_body %} ## Comparison operators Ruby gives you several operators for comparing values. They look familiar from other languages, but a few behave subtly differently. ### Equality: `==`, `eql?`, `equal?` - `==` is **value equality**. Most code uses this. - `eql?` is **stricter** — same value AND same type. `1 == 1.0` is `true`, but `1.eql?(1.0)` is `false` (Integer vs Float). - `equal?` is **identity** — the same object in memory. Rarely used directly; don't override it. ```ruby 1 == 1.0 # => true 1.eql?(1.0) # => false "hi".equal?("hi") # => false (two different String objects) ``` ### Ordering: `<`, `<=`, `>`, `>=` Numbers and strings (and dates, and many other types) order themselves the natural way: ```ruby 3 < 5 # => true "alice" < "bob" # => true (string compare is alphabetical) ``` ### The spaceship: `<=>` `<=>` returns `-1`, `0`, or `1` depending on whether the left side is less than, equal to, or greater than the right: ```ruby 1 <=> 2 # => -1 2 <=> 2 # => 0 3 <=> 2 # => 1 ``` This is the operator `sort` uses, and the one you'd implement in your own class to plug into `Comparable`. ### `between?` Shortcut for "is the value between two bounds, inclusive": ```ruby age = 25 age.between?(18, 65) # => true ``` ### Pitfall: assignment vs equality `=` assigns. `==` compares. Mixing them up is a classic bug: ```ruby if x = 5 # assigns 5 to x — always truthy! if x == 5 # compares x to 5 ``` {% endcapture %} {{ lesson_body | markdownify }}
