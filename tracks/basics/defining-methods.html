Defining methods

{% capture lesson_body %} ## Defining methods A method is a named block of code you can call repeatedly. You define one with `def` and end it with `end`: ```ruby def square(n) n * n end square(4) # => 16 ``` ### Return values The value of the **last expression** in the body is the return value — no `return` keyword required. ```ruby def double(n) n * 2 # this is what gets returned end ``` You *can* use `return` when you want to exit early: ```ruby def safe_divide(a, b) return nil if b == 0 a / b end ``` ### Default arguments You can give arguments a default value: ```ruby def greet(name, greeting = "hi") "#{greeting}, #{name}" end greet("alice") # => "hi, alice" greet("bob", "hello") # => "hello, bob" ``` Defaults must come *after* required arguments in the signature. ### Keyword arguments For methods with several arguments, positional order gets confusing. Keyword arguments let callers say what each value is for: ```ruby def shift(point, by: 1, axis: :x) "#{point} shifted by #{by} on #{axis}" end shift("p", by: 3, axis: :y) shift("p") # uses defaults ``` You can also make keyword args *required* by leaving off the default: ```ruby def shift(point, by:) point + by end shift("p", by: 3) shift("p") # ArgumentError: missing keyword: by ``` Keyword args are the easiest way to make method calls self-documenting at the call site. ### Splat arguments When you don't know how many arguments will be passed, prefix with `*`: ```ruby def sum(*nums) nums.reduce(0, :+) end sum # => 0 sum(1, 2, 3, 4) # => 10 ``` Inside the method, `nums` is an array. ### Naming convention - Methods that return a boolean usually end in `?`: `empty?`, `include?`, `admin?`. - Methods that mutate their receiver (or raise) often end in `!`: `upcase!`, `save!`. - Use `snake_case` for method names — never `camelCase`. {% endcapture %} {{ lesson_body | markdownify }}
