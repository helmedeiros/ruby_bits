Truthy and falsy

{% capture lesson_body %} ## Truthy and falsy When Ruby decides whether to enter an `if` branch, it doesn't ask "is this true or false?" — it asks "is this truthy?". Two values are **falsy**: `false` and `nil`. **Everything else is truthy**, including some values that surprise people coming from other languages. ### The rule ```ruby puts "truthy" if 0 # prints "truthy" — zero is truthy puts "truthy" if "" # prints "truthy" — empty string is truthy puts "truthy" if [] # prints "truthy" — empty array is truthy puts "truthy" if {} # prints "truthy" — empty hash is truthy puts "truthy" if nil # prints nothing — nil is falsy puts "truthy" if false # prints nothing — false is falsy ``` This is different from JavaScript or Python, where `0`, `""`, and empty containers are falsy. Ruby is stricter: only `nil` and `false` are falsy. ### Why nil exists `nil` is Ruby's "nothing here" value. Methods that don't find what they were looking for return `nil`: ```ruby [1, 2, 3].find { |n| n > 100 } # => nil {a: 1}[:missing_key] # => nil ``` So `if value` is a common shorthand for "did we find something?": ```ruby user = User.find_by(email: "x") if user puts "welcome, #{user.name}" end ``` ### Common pitfall: confusing nil and false Both `nil` and `false` are falsy, so you often can't tell them apart in an `if`. If the difference matters (e.g. "user explicitly said no" vs "user didn't say"), use `.nil?`: ```ruby value.nil? # true only for nil, not for false ``` {% endcapture %} {{ lesson_body | markdownify }}
