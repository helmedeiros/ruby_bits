Variables and scope

{% capture lesson_body %} ## Variables and scope Ruby has four kinds of variable. Each one is identified by a prefix (or lack of one), and each lives in a different scope. ### Local variables: `name` Lower-case identifiers, no prefix. Local to the block / method / file where they're defined. ```ruby def greet msg = "hello" # local — visible only inside #greet msg end ``` Each block creates its own local scope. ### Instance variables: `@name` Begin with `@`. Belong to a specific object instance — useful for holding state on a class. ```ruby class User def initialize(name) @name = name # belongs to this specific User end def greet "hi, #{@name}" end end ``` An unset instance variable returns `nil` (no warning). Be careful with typos. ### Class variables: `@@name` Two `@`s. Shared across **all** instances of a class (and its subclasses). Used rarely — they're easy to misuse. ```ruby class Counter @@count = 0 def self.bump; @@count += 1; end def self.count; @@count; end end ``` ### Global variables: `$name` Begin with `$`. Visible everywhere in the program. Almost always a bad idea — like global state in any language, they make code hard to reason about. Avoid except for true globals (`$stdout`, `$LOAD_PATH`). ### Block-local shadowing Inside a block, you can shadow an outer local explicitly: ```ruby x = 10 [1, 2, 3].each { |x| puts x } # this x shadows the outer x ``` After the block, the outer `x` is still `10`. ### Pitfall: undefined locals Referencing a local variable that has never been assigned raises `NameError`. Referencing an unset instance variable returns `nil` — no error. This asymmetry catches beginners. {% endcapture %} {{ lesson_body | markdownify }}
