Strings and symbols

{% capture lesson_body %} ## Strings and symbols Ruby gives you two kinds of textual values, and beginners often confuse them. Let's go through each carefully. ### Strings A **string** is a sequence of characters. You create one with quotes: ```ruby greeting = "hello" name = "alice" ``` Strings can be combined with `+`, repeated with `*`, and asked their length: ```ruby "hi" + " " + "alice" # => "hi alice" "ha" * 3 # => "hahaha" "alice".length # => 5 ``` The most useful trick is **interpolation** — embedding values right inside a string with `#{...}`. Note this only works inside *double* quotes: ```ruby name = "alice" "hello, #{name}" # => "hello, alice" 'hello, #{name}' # => 'hello, #{name}' — no interpolation! ``` Strings have many methods you'll use constantly: ```ruby "Alice".upcase # => "ALICE" "Alice".downcase # => "alice" " hi ".strip # => "hi" "hello".include?("ll") # => true "hello".reverse # => "olleh" ``` ### Symbols A **symbol** looks like `:name`. It's an immutable label — Ruby guarantees the same symbol always refers to the same object in memory. Symbols are cheap to compare and never accidentally mutate. ```ruby :pending :status :user_id ``` Symbols and strings are not interchangeable: `:name` is not `"name"`. They look similar in the source but behave differently. ### When to use which? - Use **symbols** for fixed identifiers that name a *kind* of thing: hash keys, states (`:pending`, `:active`), method names. They're not for display. - Use **strings** for human-facing text — anything you'd print, log, store, or send over the wire. ### Common pitfall: quote style A common beginner bug is wondering why interpolation "doesn't work" — usually the wrong quote was used. Single quotes are literal; double quotes interpolate. {% endcapture %} {{ lesson_body | markdownify }}
