The Enumerable module

{% capture lesson_body %} ## The Enumerable module The same trick as `Comparable` — implement **one** method, get a pile of behavior for free — also works for iteration. The module is `Enumerable`, and the contract is `each`. ### The deal You implement: ```ruby def each # yield each element end ``` In return, `Enumerable` gives your class **all of these**: - `map`, `select`, `reject`, `reduce` / `inject` - `find`, `find_index`, `any?`, `all?`, `none?`, `count` - `min`, `max`, `min_by`, `max_by`, `sort`, `sort_by` - `group_by`, `partition`, `chunk_while`, `each_with_index`, `each_with_object`, `to_a`, `first`, `take`, `drop`, … Around forty methods, for the price of one. ### Concrete example Imagine a class for a deck of cards. Once you wire `each`, the deck acts like any Ruby collection: ```ruby class Deck include Enumerable def initialize(cards) @cards = cards end def each(&block) @cards.each(&block) end end d = Deck.new(%w[2H 7C JD AS]) d.map(&:length) # => [2, 2, 2, 2] d.select { |c| c[1] == "H" } # => ["2H"] d.count # => 4 d.sort # => ["2H", "7C", "AS", "JD"] ``` None of those methods are defined on `Deck` — they come from `Enumerable`, which knows how to do them given just `each`. ### Why it matters - **Cheap to add a collection-like API** to any class. - **Consistent vocabulary**: callers don't need to learn your custom traversal — they already know `map`, `select`, `reduce`. - **Easy to refactor.** Internal storage can change (Array, Set, linked list) — as long as `each` keeps working, the rest of the methods follow along. ### Pitfall: `each` must yield, not return The contract is "yield each element to the block." If your `each` returns the array directly without yielding, all the inherited methods break. Make sure your `each` calls `yield` or delegates to another `each` via `&block`. {% endcapture %} {{ lesson_body | markdownify }}
