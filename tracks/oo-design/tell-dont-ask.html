Tell, don't ask

{% capture lesson_body %} ## Tell, don't ask Asking for state and acting on it puts the logic in the wrong place: ```ruby if account.balance >= amount account.balance -= amount else raise InsufficientFunds end ``` Tell the object what you want; let it decide: ```ruby account.withdraw(amount) # raises if not enough ``` Callers shrink, the object's behavior is testable in isolation, and the rule (insufficient funds) lives next to the data it guards. {% endcapture %} {{ lesson_body | markdownify }}
