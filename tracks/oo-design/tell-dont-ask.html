Tell, don't ask

{% capture lesson_body %} ## Tell, don't ask When you see code like this, your design alarm should go off: ```ruby if account.balance >= amount account.balance -= amount else raise InsufficientFunds end ``` The caller is **asking** the account for state, **making a decision**, then **mutating** the account. That's three things happening at one level above the data — and any other place that wants to withdraw money has to re-implement the same dance. ### What "tell, don't ask" means Instead of asking for state and acting on it, **tell the object what you want**. Let it decide: ```ruby account.withdraw(amount) # raises if not enough ``` Now the rule about insufficient funds lives **next to the balance**. Other code calling `withdraw` doesn't need to know the rule. ### Why this matters - **Encapsulation**: `account` is the only place that touches its balance. If you want to add an overdraft fee or audit log, you change it in one place. - **Smaller callers**: every "I want to spend money" site becomes one line. - **Easier to reason about**: when you read `account.withdraw` you don't need to wonder *what* the caller might have done differently — there's one withdrawal path. ### When asking is OK "Tell, don't ask" isn't an absolute rule. There are legitimate reasons to read state — display, search, validation that spans multiple objects. The rule is more useful as a **smell detector** than as a law: > If your caller reads a value, branches on it, then writes > back to the same object — the logic probably belongs in the > object, not the caller. ### Demeter — a related rule of thumb A related principle says: **talk only to your immediate neighbors**. If you find yourself writing `customer.profile.address.city.country.code`, you're reaching past several objects. Each `.` is a dependency on the structure of the object before it. A small change anywhere in that chain breaks the caller. Prefer a method on `customer` (like `country_code`) that hides the structure. {% endcapture %} {{ lesson_body | markdownify }}
