Defining classes

{% capture lesson_body %} ## Defining classes A **class** in Ruby groups data (instance variables) and behavior (methods) under one name. Every class you write follows the same shape. ### Skeleton ```ruby class Account def initialize(balance) @balance = balance end def deposit(amount) @balance += amount end def balance @balance end end ``` Three things to notice: 1. **`class Name`** opens a class definition. `Name` must start with an uppercase letter — it's a constant. 2. **`initialize`** is the special method Ruby calls when you write `Account.new(...)`. Whatever args you pass to `new` get forwarded to `initialize`. 3. **`@balance`** is an instance variable — each `Account.new` creates a fresh `@balance` on that object. ### Creating and using instances ```ruby acc = Account.new(100) # calls initialize(100) acc.deposit(50) acc.balance # => 150 ``` `acc.deposit(50)` is Ruby's way of saying "send the `deposit` message to `acc` with the argument `50`." ### Each instance has its own state ```ruby a = Account.new(100) b = Account.new(0) a.deposit(50) a.balance # => 150 b.balance # => 0 (untouched) ``` Two instances of the same class hold independent `@balance` values. This is the whole point of OO: bundle data with the behavior that operates on it, and let each object hold its own data. ### `attr_reader`, `attr_writer`, `attr_accessor` Writing `def balance; @balance; end` for every variable is tedious. The next lesson covers the shorthand. ### Pitfall: typos in `@names` A misspelled `@balanace` doesn't raise — it just creates a new (always `nil`) instance variable. Watch for typos. {% endcapture %} {{ lesson_body | markdownify }}
