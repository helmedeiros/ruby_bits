{% capture lesson_body %} ## case / when When you have several conditions to check against the same value, `case`/`when` reads much cleaner than a chain of `if`/`elsif`: ### Basic form ```ruby case status when :pending then "still going" when :paid then "money in the bank" when :shipped then "on its way" else "unknown status" end ``` Like `if`, `case` is an **expression** — the whole block returns the value of the matched branch. You can assign it directly. ### How matching works `when X` uses `X === value` (the **case equality** operator) to decide whether to match. For most types this is the same as `==`, but a few classes override it for nice patterns: - **Classes** match instances: `when Integer` matches if the value is an Integer. - **Ranges** match membership: `when 1..10` matches numbers in that range. - **Regexes** match patterns: `when /\Aerror/` matches strings starting with "error". ```ruby case input when Integer then "got a number" when String then "got text" when 1..10 then "small number" # (only if input is an Integer) when /^http/ then "URL" else "something else" end ``` ### Multiple matches per branch Separate values with a comma to share a body: ```ruby case day when "Sat", "Sun" then "weekend" when "Mon".."Fri" then "weekday" end ``` ### Pitfall: no fall-through Unlike C/Java, Ruby's `case` does **not** fall through between branches. The first matching `when` runs, then the case ends. No `break` needed. {% endcapture %} {{ lesson_body | markdownify }}
